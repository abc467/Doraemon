# Upstream provenance

This package is a focused ROS1 / Move Base Flex port of the Nav2 Smac State
Lattice planner design and control-set format.

- Upstream repository: https://github.com/ros-navigation/navigation2
- Upstream package: `nav2_smac_planner`
- Pinned release: `1.5.0`
- Pinned commit: `0e69ba8a30259b827de5169817f6991d46374465`
- Upstream license: Apache-2.0

The ROS2 lifecycle/plugin wrapper is intentionally not copied. This package
implements an MBF `CostmapPlanner` adapter around the state-lattice search,
preserves Nav2's differential-drive minimum-control-set JSON format and cost
penalties, and adds continuous swept-polygon validation. Adjacent official
lattice or analytic states are adaptively subdivided from the actual rigid
displacement of every footprint polygon vertex. Each inserted pose is checked
by the Nav2 footprint collision checker, including zero-translation turns.

Nav2 1.5.0 caches collision validity on the discrete lattice node. That is
valid for an endpoint-only check, but not for continuous swept-footprint
validation because multiple incoming motion primitives can terminate in the
same discretized x/y/heading state. This port therefore evaluates every
incoming primitive independently. When A* queues a lattice candidate, its
continuous pose, parent, primitive, travel direction, and swept-edge cost are
stored and restored together so a later candidate for the same discrete node
cannot splice metadata from two different edges. The planner adapter retains a
second full-path continuous-footprint validation as a release safety invariant.

The optional `StateLatticeSmoother` is a ROS1 adapter of Nav2 Smac's official
State Lattice smoother. It preserves the upstream iterative data/smooth update,
directional segmentation, yaw reconstruction, refinement passes, and Dubins
boundary treatment. ROS2 lifecycle and parameter plumbing are deliberately not
imported. The adapter smooths a private copy of State-generated poses only,
keeps the raw path as an atomic fallback, and adds project-specific cost,
curvature, direction, cancellation, and deadline gates. A candidate is never
committed until the existing continuous filled-footprint proof succeeds; the
Theta prefix is never smoothed.

For long commercial cleaning-area connections, the MBF adapter also provides
a ROS1-specific composite mode. A read-only Theta* search, using the deployed
clearance weights, supplies the long-range topological route. The final
100-pose reference suffix is regenerated by the official State Lattice search;
failed suffixes widen to 160, 240, and 400 poses before an unrestricted exact
State Lattice fallback. This composition is adapter code, not an upstream Nav2
feature. It never invokes the legacy Theta MBF terminal connector or custom
SE(2) refiner, keeps unknown space fail-closed, and publishes only after the
complete stitched path passes continuous filled-footprint validation on both
the planning snapshot and a fresh costmap snapshot.
